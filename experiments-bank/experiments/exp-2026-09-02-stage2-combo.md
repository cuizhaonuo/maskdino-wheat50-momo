### LSJ 标签噪声修复（本次新增，非此前实验）

`ResizeScale(0.1~2.0)+FixedSizeCrop(1024)` 在 scale>1 时把完整的 wheat_2 切到 crop 边界，
标签仍是 wheat_2，与标注规则「截断的穗子归 wheat」矛盾。移植自未并入的
`fix-lsj-wheat2-label-noise` 分支（`e497ad9`），并新增「降级时清空 `gt_points`」。

实测（train 前 100 图，固定种子，开关对比）：

| | DEMOTE=False | DEMOTE=True |
|:--|--:|--:|
| 实例总数 | 3071 | 3071（不变，只改标签） |
| wheat_2 实例 | 220 | **165**（降级 55 个，25.0%） |
| wheat_2 上的点 | 2510 | **2104**（清空 406 个，16.2%） |
| 「类别=wheat 却带点」的实例 | — | **0** |

被降级的穗**平均只带 7.4 个点，而整体均值 11.4**。mapper 本就会滤掉图外的点，
所以截断穗是在用「可见部分的点数」冒充完整穗的计数标签 ——
这是四个解冻 arm 共同的遗留短板「预测向均值收缩」（散点拟合斜率 0.42~0.48、r ≤ 0.46）
的一条具体机制。

**Stage1 的 wheat_2 并不比 wheat 差**（AP 73.43 vs 73.17，反而略高）。
**那 8.6 点的缺口是 Stage2 解冻训练自己造成的** —— 点损失压着共享 decoder，
把 wheat_2 的检出打坏，而 wheat 几乎没受影响（−1.6）。

bbox 上 wheat +0.86 / wheat_2 **+4.43**，比值约 1:5。而 wheat_2 正是本次改动
唯一直接触及的类别（LSJ 只降级 wheat_2，点损失只监督 wheat_2）。

## 【方法论缺陷】本 run 没有预注册

前十几个 run 都遵守「跑之前写死预期与判否线」，本 run **没有**。
我在启动前三次提出补写、均未落实，结果是**六个变量同时动、判否线事后才对账**。
后果具体有二：

1. **无法归因。** 「涨幅集中在 wheat_2、且集中在 AP50」这条证据链指向 LSJ 修复，
   但四个点头旋钮同样只作用于 wheat_2 的点损失，理论上能通过共享 decoder 传导。
   要坐实需单跑「纯 B + 只开 `DEMOTE_BORDER_TRUNCATED`」的一变量消融。
2. **事前预测被事后叙述污染的风险。** 我事前的判断是「现实上限在计数不在定位」，
   best-vs-best 确实是计数 −15.3% / 定位 −0.017，方向对上了 —— 但这条预测
   只存在于对话里，没有落盘，**不构成有效的预注册证据**。

## 【更正】中途按同阈值读出过相反的结论

扫描完成前我按**同阈值（0.35）**比较，得出「定位涨了、计数反而退了」：
`matched_F1@8` 0.4933 → 0.5450（+0.052）、`count_MAE_spike` 2.48 → 3.68（+48%）。

**这是口径错误。** 纯 B 的 2.48 是它八档扫描的计数最优点（@0.35），
而组合在 0.35 上并非最优 —— 四个标定旋钮把置信度整体推高，
组合的计数最优点移到了 **0.50**。按 best-vs-best 结论完全相反。
**跨 run 比较必须各自取最优阈值**，这条在 [exp-2026-08-25-point-class-mlp](exp-2026-08-25-point-class-mlp.md)
的「阈值口径」注里已经写过，本次仍然踩了。

阈值右移的方向倒是预测对了：计数最优 0.35 → **0.50**，定位最优 0.20 → **0.28**，
与 α=0.5 抬高置信度一致。但我事前担心「八档框不住最优点」是多余的 ——
两个最优点都落在原八档内，加跑的 0.70 / 0.80 是浪费。

## 结论

1. **计数上组合胜出**：`count_MAE_spike` 2.48 → **2.10（−15.3%）**，
   且 `count_MAE_img` 14.95 与之同向。**要计数就用组合 @ T=0.50。**
2. **定位上纯 B 仍略胜**：`matched_F1@8` 0.5806 vs 0.5638（−0.017）。
3. **掩码显著回收**：segm AP +2.47 / bbox AP +2.65，把 arm B 相对 arm A 的
   −5.5 代价追回近一半。这一条**事前完全没预料到**。
4. **最可能的机制**（未验证）：`POINT_EMPTY_CLS_WEIGHT=0.1` 把无点实例的存在性损失
   降到 1/10。该项在训练初期占 `loss_point_cls` 的 **93.9%**
   （[exp-2026-08-26-point-empty-cls-weight](exp-2026-08-26-point-empty-cls-weight.md) 实测），
   解冻后这股压力会扭曲共享 decoder；降权相当于把 decoder 还给检测任务。

## 注意事项

- **计数比较对组合偏宽松。** `count_MAE_spike` 只在配对上的穗内部算，
  组合的 `spike_recall` 低 7 个百分点（实例配对 180 vs 纯 B 的 198）——
  **组合是在更小、更容易的集合上拿到 2.10 的**。与 arm D 当初那条口径限制同源。
- `spike_recall` −0.070 / `spike_precision` +0.106 是 LSJ 修复的签名：
  训练时 25% 的 wheat_2 被降级，该类先验下降，模型预测 wheat_2 更保守。
- 逐类别 AP 不受 `POINT_THRESHOLD` 影响（该阈值只筛点、不影响实例），
  所以 AP 部分是干净的单点对比。
- 阈值扫描只在 `model_final`（iter 8000）上做；逐 checkpoint × 逐阈值的二维最优未穷举。
- 本 run 的对照 `exp-0827-real-unfzB` 与本 run 的测试尺度相同（`MIN/MAX_SIZE_TEST=1024`），
  可直接比。**不要与 Stage1 配置的默认 800/1333 口径混用**，见 baseline 那篇的更正。
