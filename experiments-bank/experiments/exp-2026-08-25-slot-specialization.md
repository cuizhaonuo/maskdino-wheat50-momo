## 动机

`exp-2026-08-21-innercost` 把内层点匹配代价恢复后，坐标头大幅改善而**存在性头垮了**
（`loss_point_cls` 0.278 → 0.517，每穗计数 MAE 2.30 → 8.20）。当时给出的机制解释是：

> 改成按距离匹配后，哪些 slot 为正取决于点落在哪，**跨迭代不稳定**，
> 存在性头学不出稳定映射，只能压低置信度。

这条解释此前**没有被测量过**。本实验直接测它。

## 测什么

在 `criterion.forward` 里挂钩子，跨迭代累计两个量（`myscripts/backup/vis_process/vis_slot_specialization.py`）：

1. **每个 slot 被内层匹配选中的频率**，对照两条参照曲线
   - 随机基线 `E[Ni]/P` —— slot 完全未分化时的水平（平的）
   - 完美 rank 分化 `P(Ni > k)` —— slot 按序分化时的阶梯
2. **同一实例前后两次观测的匹配 slot 集合 Jaccard** —— 直接测标签是否抖动

### 为什么这个测量是干净的

`wheat_stage2_pointhead_overfit10.yaml` 关掉了全部几何增广
（`MIN_SCALE=MAX_SCALE=1.0`、`RANDOM_FLIP: "none"`），`DROPOUT=0.0`，backbone 是 FrozenBN。
**同一张图每次前向的输入完全一致**，所以匹配集合若发生变化，只可能来自权重更新。

## 怎么跑

从已过拟合 2000 iter 的 `model_final` 继续训练，若 slot 此时仍未分化，
即可排除「训练不够」这一解释。

```bash
CUDA_VISIBLE_DEVICES=0 PYTHONPATH=. python train_net.py --num-gpus 1 \
  --config-file configs/coco/instance-segmentation/wheat_stage2_pointhead_overfit10.yaml \
  MODEL.WEIGHTS output_v2/wheat_stage2_pointhead_overfit10/model_final.pth \
  SOLVER.MAX_ITER 500 SOLVER.CHECKPOINT_PERIOD 999999 TEST.EVAL_PERIOD 0 \
  OUTPUT_DIR <tmp>
```

跑 1 到 iter 379 取数（call 100/200/300 三次 dump，**5040 次实例观测 / 84 个不同实例**）。
跑 2 用 `SOLVER.MAX_ITER 10` 只为采一次收敛态的置信度矩阵（warmup 期 LR ≈ 1e-7，权重几乎不动）。

## 结果一：匹配是稳定的 —— 原解释被证伪

| 量 | 值 |
|:--|--:|
| 匹配 slot 集合 Jaccard 均值 | **0.998** |
| 中位数 | 1.000 |
| 前后两次完全不变的比例 | **98.8%** |
| 每轮换掉的正样本槽位占比 | **0.1%** |

**「跨迭代不稳定」不成立。** 同一个实例每次拿到的都是同一组 slot。
`exp-2026-08-21-innercost` 那条机制解释需要作废。

## 结果二：slot 只有部分分化

| 量 | 实测 | 完美 rank 分化 | 随机基线 |
|:--|--:|--:|--:|
| 频率 std | **0.1814** | 0.4113 | 0 |
| 到该参照曲线的平均距离 | — | 0.2338 | **0.1440** |
| 频率 > 0.9 的 slot | **0/50** | 19/50 | 0/50 |
| 频率 < 0.1 的 slot | 9/50 | 31/50 | 0/50 |

（`Ni` mean=14.0 / min=8 / max=19，`P=50`，随机基线 `E[Ni]/P = 0.280`。）

实测离随机基线比离完美分化更近，且**没有任何一个 slot 是「几乎总被匹配」的**。
结合 Jaccard 0.998，唯一自洽的解释是：
**每个实例稳定占用自己的一组 slot，但不同实例用的子集不同**，边际频率因此被摊平到 0.28。

关键推论：目标是**稳定且可学的**——trunk 全冻结，query embedding 是固定特征，
同一实例的标签每次都一样。所以问题不在数据，在于头没学到。

## 结果三：存在性头只学到了边际频率

据此补了第二个诊断（`dump_discrimination`）：头究竟在预测「**这个实例**的哪些 slot 该亮」，
还是只学到了「每个 slot **平均**多大概率亮」。84 个实例、`P=50`、`α=0.25`：

| 量 | 值 | 判读 |
|:--|--:|:--|
| slot 平均置信度 与 其边际频率对应的 focal 平衡点，相关系数 | **0.964** | 散点紧贴理论曲线 |
| 置信度方差中由 slot 边际差异解释的比例 | **47.5%** | 置信度矩阵呈明显竖条纹 |
| 固定 slot 后跨实例平均 AUC | **0.721** | 0.5 = 完全不认识实例 |
| 全局 AUC | 0.792 | 排序有点用，但标度错了 |

其中「理论平衡点」指：某槽位若以频率 `f` 为正样本，focal loss 会把置信度推到
使期望损失最小的那个 `p`。数值解：

| f | α=0.25 | α=0.5 | α=0.75 |
|--:|--:|--:|--:|
| 0.28 | **0.318** | 0.413 | 0.514 |
| 0.45 | 0.381 | 0.481 | 0.583 |
| 0.62 | 0.443 | 0.546 | 0.644 |
| 0.80 | 0.527 | 0.627 | 0.716 |
| 1.00 | 1.000 | 1.000 | 1.000 |

`f = E[Ni]/P = 0.28` 对应 **0.318**，而实测匹配点置信度中位数 **0.33**、未匹配 **0.20**。
**头基本停在「按边际频率输出」这个解上。**

注意表格最后一行：**`f=1.0` 时无论 α 取多少平衡点都是 1.0**。
也就是说 α 只在头无法区分实例时才决定收敛位置——所以 α 与「判别力不足」是同一个问题的两面，
不是两个独立问题。

## 单图的三张快照（同一 commit 的可视化工具）

同一张图（39 个 GT，8 个 `wheat_2` / 31 个 `wheat`）：

- **正负样本匹配**：外层匹配 39/39 全部落在 Top-100 内，rank median 20 / max 83。**外层匹配没问题。**
- **置信度分布**：`top-Ni 命中率 63/102 (61.8%)`；有点实例超阈值(0.35)点数 86，GT 102（**漏 16%**）；
  无点实例超阈值仅 3（**假阳性几乎没有，计数误差是漏检主导**）。
- **损失分解**（与 `criterion.loss_points` 交叉校验，合计 0.4818 完全一致）：

  | 成分 | 值 | 占比 |
  |:--|--:|--:|
  | 坐标 L1（仅匹配点） | 0.0931 | 19.3% |
  | 存在性 focal · 正样本 | **0.2520** | **52.3%** |
  | 存在性 focal · 负样本 | 0.1367 | 28.4% |

  8 个有点实例贡献 0.4353，31 个无点实例只有 0.0465（9.7%）。
  **损失已由存在性头的正样本项主导，坐标项只剩两成。**

## 相关的代码事实（本次核实）

- `point_class_embed = nn.Linear(hidden_dim, num_points)` 是**单层线性**，
  而 `point_coord_embed = MLP(hidden_dim, hidden_dim, num_points*2, 3)` 是 3 层 MLP
  （`maskdino/modeling/transformer_decoder/maskdino_decoder.py:147-148`）。两者容量不对称。
- `self.focal_alpha = 0.25` 在 `criterion.py:170` **硬编码**，且
  `loss_labels`（300 query）与 `loss_points`（50 slot）**共用**同一个值。
  全仓库**没有**任何 `FOCAL` / `ALPHA` 配置项。
- 全库 `Ni` 分布：train `min=1 / max=24 / mean=13.9 / p95=18`（981 个有点实例 / 11904 无点），
  val `min=7 / max=22 / mean=14.0`。**证实 `memory-bank/idea.md` 里「GT 单穗最多 24 点」的说法。**

## 注意事项

- **本次测量全部在 overfit10 这 10 张图上，模型也正是在这 10 张图上过拟合的。**
  「匹配稳定」「只学到边际频率」两条结论在完整训练集上是否成立**未验证**——
  但注意：过拟合场景是对模型最有利的情形，此处都没学出实例判别力，
  在完整集上只会更差，所以结论方向是保守的。
- `dump_discrimination` 每个实例只保留**最后一次**观测的置信度，
  不是跨迭代平均；因为匹配稳定（Jaccard 0.998），这样取值不影响结论。
- 诊断钩子每次迭代会额外跑一遍内层匈牙利匹配。正式训练前把
  `vis_slot_specialization.ENABLED` 改成 `False`。
