## 单变量改动

```python
# criterion.py loss_points，原 cls_loss = cls_loss + focal.sum()
w = 1.0 if Ni > 0 else self.point_empty_cls_weight
cls_loss = cls_loss + focal.sum() * w
```

只作用于 `cls_loss` 的分子。`coord_loss` 不受影响（Ni=0 本就无匹配点）；
`denom = max(num_pos, 1)` 只统计 Ni，也不受影响。
`w = 0` 等价于 `memory-bank/idea.md` 第一条的选项 (a)「只对 wheat_2 算点损失」。

## 结果

`spike_recall` 三个 run 全为 0.7262（训练集）/ 0.7588（val），trunk 未受扰动。

| | baseline (w=1.0) | w=0.3 | w=0.1 | w=0.0 |
|:--|--:|--:|--:|--:|
| 跨实例 AUC | 0.671 | 0.728 | 0.752 | **0.841** |
| **无点实例超阈值槽数** | 93 | 196 | 479 | **8020** |
| 训练集最佳 mF1 | 0.3648 | 0.3751 | **0.3780** | 0.3760 |
| 训练集最佳计数 MAE | 7.61 | 5.26 | 4.41 | **2.72** |
| **val 最佳 mF1** | 0.1495 | 0.1496 | 0.1494 | 0.1469 |
| **val 最佳计数 MAE** | 8.60 | 6.59 | 5.49 | **4.14** |
| val 整图计数 MAE | 25.7 | 20.6 | 18.7 | **17.5** |

**定位（mF1）在 val 上三档全部落在噪声地板 0.008 以内 —— 零收益。**
**计数在 val 上随 w 下降单调改善，8.60 → 4.14（−52%），且整图计数同向（25.7 → 17.5）。**

### 落空的那条：我又用错了时间点

ideas 里预测「AUC 基本不动——无点实例本就贡献极少梯度」，依据是收敛态实测的 9.7%。
实际 AUC 涨了 +0.057 / +0.080 / **+0.169**。

原因在启动 run 之前的冒烟里就测到了并已记录：**iter 19 时无点实例占 `loss_point_cls` 的 93.9%**，
收敛态才降到 9.7%。focal 的抑制依赖置信度已被压低，初始化时所有点都在 p≈0.5、
`(1-p_t)²=0.25` 完全无抑制。**初期正是存在性头确定输出标度的阶段**，
所以那 93.9% 才是决定性的。用收敛态数字推断梯度贡献是取错了时间点。

## w=0 的失败模式：指标看不见，门控挡住了

`w=0` 时无点实例对点头**完全无梯度**，头没有任何理由压低它们的置信度：
**8020 个超阈值槽位（baseline 的 86 倍），平均每个 wheat 穗子 15.5 个假点，最高置信度 0.987。**

但**跨实例 AUC 只在 wheat_2 实例上计算，完全看不见这个失败模式** ——
它显示 0.841（接近 canonical 的 0.842），指标漂亮而模型已经坏了一半。
若只看 AUC 会选出最差的那一档。这是本次加无点实例探针的直接价值。

端到端却没有兑现：`instance_inference` 按 `pred_classes == spikelet_class_id` 门控，
这些假点绝大多数没能进入输出，val 的整图计数反而最好（17.5）。
**所以这是潜在脆弱性，不是当前损害** —— 它完全依赖分类头，
而 val 的 `spike_precision` 只有 0.7529，约四分之一的预测 wheat_2 其实是 wheat。
一旦分类退化（换数据集、换域），w=0 会立刻暴露。

**训练集根本测不出这个风险**：那里模型过拟合、分类近乎完美，门控挡住一切。

## 判据的两处缺陷（如实记录，不作事后重解释）

- **判否线**（三档 mF1 变化均 <0.008 **且** AUC 变化均 <0.03）：**未触发**。
  mF1 确实全部低于噪声地板，但 AUC 涨了远超 0.03。
- **净有害线**（假点涨 >3 倍 **且** mF1 无增益）：**字面上触发**
  （w=0.1 为 5.2 倍、w=0.0 为 86 倍，val mF1 均无增益）。
  **但这条线写坏了**：它只引用 mF1、完全没提计数，而计数正是收益落地处（val −36%~−52%）。
  照字面执行会把一个真实收益判成有害。

这是本系列**第三次**预设判据出现缺陷（前两次见
[point-focal-alpha](exp-2026-08-25-point-focal-alpha.md) 的度量口径错配、
[point-num-points-25](exp-2026-08-25-point-num-points-25.md) 的阈值标定不适用）。
共同教训：**判否线必须同时钉死「用哪个指标、在哪个数据集、用什么度量口径」**，
只写一个指标名是不够的。

## 结论与推荐

**推荐 w = 0.1。** 它拿到 val 计数 −36%（8.60 → 5.49）、AUC +0.080，
而假点放大只有 5.2 倍（对 w=0 的 86 倍）。w=0 的计数更好（−52%）但把
「wheat 上不出点」这条约束彻底交给了分类头，风险不对称。

横向看（九方对比，val 计数 MAE）：
`canonical 2.38 < w=0.0 4.14 < w=0.1 5.49 ≈ clsmlp 5.42 < α=0.5 6.35 < baseline 8.60`

**`w=0.1` 与 `clsmlp` 在 val 上几乎完全打平**（mF1 0.1494 / 0.1483，计数 5.49 / 5.42），
但 clsmlp 要多 131k 参数，本条只是**一行代码**。

## 注意事项

- **overfit10 的类别构成低估了本改动的效应**：wheat_2 占 20%，真实训练集只有 7.6%，
  wheat 的损失份额约大 2.5 倍。ideas 里已预先声明，结论仅限本配置。
- 三个 w 下 `loss_point_cls` 是**不同的目标函数**，跨 run 绝不可比较其数值。
- 每个 run 的最优阈值不同，横向比必须逐个扫（本文用八档
  `{0.10,0.15,0.20,0.28,0.35,0.40,0.50,0.60}`，val 用四档）。
- 与 [point-focal-alpha](exp-2026-08-25-point-focal-alpha.md) 机制**部分重叠**
  （都抬高置信度标度），但本条是**实例间**再平衡、α 是**实例内**再平衡，
  两者收益不可简单叠加，若要组合需单独验证。
