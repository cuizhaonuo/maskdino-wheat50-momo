## 判决

### ① 掩码判据第一档触发 —— **假设成立**

预注册：「某档 wheat_2 segm AP50 ≥ 82（距 Stage1 的 82.89 不足 1 点）→ 假设成立：
Stage2 的 wheat_2 代价确实来自动了干活的那几层，缩小解冻面即可消除。」

**last1 得 82.77（差 0.12）、last3 得 82.60（差 0.29）**，两档都过线。
组合方案是 79.72、纯 arm B 是 74.30。

```
wheat_2 segm AP50:  82.89 │ 82.77  82.60  80.82  80.29  81.61 │ 79.72  74.30
                    Stage1│ last1  last3  last5  last7  last9 │ 组合   纯 arm B
                          ├──── 解冻 1~3 层：几乎无损 ────┤
```

**这条是本实验最实的结论**：Stage2 打掉 wheat_2 的 8.6 点 AP50，其中约 **8.5 点**
（82.77−74.30）可以靠「只解冻最后 1~3 层」直接免掉，不需要改损失、不需要改数据。

### ② 主判据第二条触发 —— **层数细分不能取代组合方案**

预注册：「全部五档 < 0.5638 且随层数单调上升 → 点任务需要的是**容量**而非特定层，
arm B 的优势来自 `pixel_decoder` 而非 decoder 层数，本方向到此为止。」

```
matched_F1@8:  0.4893  0.5191  0.5196  0.5333  0.5326 │ 0.5638
               last1   last3   last5   last7   last9  │ 组合(+pixel_decoder)
               ├──── 随层数上升，last7 后饱和 ────┤├─ +0.031 ─┤
```

五档全部低于 0.5638，最好的 last7 差 **0.0305**（是「持平带」0.01 的三倍）。
1→7 层单调上升 +0.044，last9 与 last7 差 −0.0007（噪声内）。
**last9（整条 decoder，14.7M）到 arm B（28.85M）那 +0.031，正好是加进 `pixel_decoder` 这一步** ——
这与 08-28 那篇「掩码退化的分界也在 `pixel_decoder`」是同一个分界，方向相反。

### ③ 「掩码与点两头兼得」未达成

预注册第三档要求「全类 segm AP ≥ 72.5 **同时**点指标不劣于组合」。
前半成立（last1/3/5/9 都 ≥ 72.32，last1 的 73.35 已是 Stage1 的 73.30 水平），
**后半不成立**。这是一条真实的取舍曲线，不是可以两头占的。

### ④ 计数看似全胜，但口径偏松，**不作为独立结论**

`count_MAE_spike` 五档 1.89~2.01，全部优于组合的 2.10（最好 −10%）。但是：

| | 配对上的穗 | `spike_recall` | `spike_precision` |
|:--|--:|--:|--:|
| last1 / last3 | 160 / 160 | 0.6226 | 0.8377 / 0.8333 |
| last5 | 166 | 0.6459 | 0.8098 |
| last7 | 159 | 0.6187 | 0.7990 |
| last9 | 162 | 0.6304 | 0.8223 |
| 组合 | **180** | **0.7004** | 0.8257 |

`count_MAE_spike` 与 `matched_F1@σ` **只在配对上的穗内部计算**，五档都在
**更小（159~166 vs 180）因而更容易**的集合上打分。这与组合方案当初相对 arm B
的口径问题同源，方向也相同。**计数这一项不能与组合横向比。**

反过来看，这条口径让判决 ② **更强**：五档是在更宽松的集合上仍然输掉 0.03。

## 工程建议

**取决于交付物是什么，本实验给出的是一条取舍曲线而非单一最优点：**

- **掩码/实例分割是交付物** → **last1**。2.36M 可训练参数（组合方案的 1/12），
  segm AP 73.35 与 Stage1 持平、wheat_2 AP50 82.77 几乎无损，
  代价是 `matched_F1@8` 低 0.075。**训练还快一倍**（显存减半）。
- **点定位是交付物** → 维持组合方案（arm B）。
- **想在两者间取中** → **last3**：wheat_2 AP50 仍有 82.60（过线），
  `matched_F1@8` 0.5191 把 last1 与组合的差距收回 40%，参数 5.45M。

## 注意事项

- **last7 / last9 的差异在噪声量级，不要解读。** last7 点最好但掩码最差、last9 两头都
  略好，单 run 无法把它与 run 间波动分开。稳的说法只有「1→7/9 层：点 +0.044、掩码 −1.5 AP」。
- 掩码随层数的下降**不是单调的**（last7 80.29 是谷底，last9 反弹到 81.61），未解释。
- 阈值扫描只在 `model_final`（iter 8000）上做；逐 checkpoint × 逐阈值的二维最优未穷举。
  各 run 的 val 峰值在 iter 6799~7199，取峰值 checkpoint 重扫可能还有余量。
- 五个 run 的测试尺度都是 `MIN/MAX_SIZE_TEST=1024`，与对照及 Stage1 基线一致，可直接比。
- **`ref_point_head`（197,120）计入了每档的常量部分**，所以严格说是
  「只动最后 N 层的自身权重 + 全部跨层共享件」。这样取的好处是
  `last9` 恰好等于组合口径的 arm C，右端能接回 A/C/B/D 体系。
