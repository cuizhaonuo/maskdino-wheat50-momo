## 预期对账

### 读数口径

预注册写的是「峰值」，并要求与三个单点臂「各臂自身曲线上的峰值」比。前半程（iter < 13000）有检出几乎为零的退化评估：B 的 F1@8 全程峰值 0.6933 就落在 iter 1999、spike_recall 0.003 的点上。
所以本臂和三个单点臂的峰值统一取**后半程（iter ≥ 13000）**。若照全程峰值取，B 的退化点会把 F1 的线抬到 0.6983，判定不变。
另报「后半程 `count_MAE_spike` 最低那次」同一 checkpoint 的全部指标（主读数，iter 22999）。

### 机制读数（预注册必读项）

- **n_k 与候选数的差距**（`model_final.pth`，2026-10-22 补做）：wheat_2、实例分数 ≥ 0.4 的 739 个预测穗（与评估器同一筛选）：n_k 均值 16.15，候选数（token 分数 > 0.35 且 NMS 存活）均值 18.55，实际输出 16.15。
  - 95.1% 的穗候选多于 n_k，top-n_k 平均截掉 2.53 个；4.5% 恰好相等；0.4% 候选不足，平均少 1.33 个。
  - n_k − 候选数 的中位数 -2，5%~95% 分位 [-4, -1]。
  - 输出点数几乎完全由 coral 决定。候选数比 n_k 平均多 2.4 个；n_k 自身对 GT 的偏差约 +0.4（配上的穗），所以只看 focal + NMS 大约会多报 2.8 个，与 p30 的 +2.65 同一量级。这只是粗略对照：前者算的是全部 739 个预测穗，后者只算配上的穗。
  - 逐实例复算与 `instance_inference` 的输出点数、类别全部一致（20000 个实例，0 处不符）。脚本 `output_v2/_diag-1022-full-docs/nk_gap_diag.py`，结果 `nkgap-exp-1009-full-combo.json`。
- **CoralHead.bias 收敛**（30 个）：相邻 29 对全部单调不增；k = 0~6 停在 2.97；k = 10~20 间隔 0.601 logit/小穗；跨度 8.35；k = 25~29 挤在 −5.00 ~ −5.38。train 集只有 6 个实例超过 25 个小穗，这几个任务几乎没有正样本。A 臂（25 个 bias）分别是 2.47 / 0.605 / 7.78。
- **`point_nms`**：`suppressed_frac` 前 500 iter 均值 65%（初期 token 全挤在一起），之后各段 7.6%~9.7%；`starved_frac` 前 500 iter 65%，之后为 0。
- **`loss_point_knn`**（只在 slot 层：interm 与 layer-0）：前 500 iter 合计 1.68 → 末 500 iter 0.164。
  - 按本臂预注册的组合语义，slot 层的前缀匹配**不加** knn 代价，group 层没有 knn。所以本臂里 KMO 只剩这一项辅助损失，匹配项不参与。
- **两类 `loss_point_cls` 曲线**（前 500 → 2000~2500 → 6000~6500 → 12000~12500 → 19000~19500 → 末 500 iter，各层合计）：
  - slot 层 CORAL BCE（interm + layer-0）：2.18 → 1.17 → 0.56 → 0.43 → 0.37 → 0.34，一路下降。
  - group 层 focal（主输出 + 8 份 aux）：2.40 → 3.74 → 2.12 → 1.70 → 1.40 → 1.28。小穗 token 接手后先升后降。
  - group 层 CORAL 计数 `loss_point_coral`（9 份）：9.02 → 4.49 → 2.42 → 1.89 → 1.60 → 1.49。
