## 预期对账

- **坐标损失升高（0.1016 → 0.1835）符合预期**，ideas 里预先写明这是
  「不能再靠铺满取巧」的表现，不得当作变差。
- **置信度上升符合预期**（边际频率 0.28 → 0.56 会抬高 focal 平衡点）。
- **最佳 mF1 +0.025**，是噪声地板 0.008 的 3 倍，属真实但温和的改善。
- **AUC 反而下降 0.031**（0.6714 → 0.6401）。这条 ideas 没预测到——
  减少 slot 数改善了标定，却没有改善判别力，甚至略有损害。

## 判否线不适用（需要记录）

ideas 沿用了 `memory-bank/idea.md` 原本写死的线：「`matched_F1@8` 到不了 0.45
则说明 P 不是主因」。p25 实测 0.5708，字面上远超该线。

**但这条线是为 val 集标定的**（`exp-2026-08-21-innercost` 在 val 上是 0.2638），
而 overfit10 是训练集自评，**同期 baseline 自己就有 0.4935，也超过 0.45**。
所以该判否线在本配置下**没有分辨力，不能用来判定成立**。

诚实的结论只能基于同期对照：P=25 带来 +0.025 的 mF1 与 −24% 的计数误差，
但判别力（AUC）不升反降。**它与 α 同属标定类改善，不解决根因。**

## 结论

`exp-2026-08-21-innercost` 提出这条时的论据是「P=50 让坐标损失失去分辨力，
随机铺满就能拿 0.484」。本实验确认坐标损失确实失去了取巧空间（0.1016 → 0.1835），
端到端也有温和改善。但**判别力的下降说明它不是那条主线**。

与 [point-focal-alpha](exp-2026-08-25-point-focal-alpha.md) 机制相同（都抬高 focal 平衡点），
两者的改善**不可叠加解读**；且 p25 需要改变权重形状、不能在已有 checkpoint 上热切换，
而 α 只是一个配置项——若只为标定，α 或直接调阈值都比它便宜。

## 注意事项

- overfit10 train==test，端到端指标是拟合质量。
- P=25 时最佳阈值移到 0.20（baseline 是 0.28），跨 run 比较必须逐个扫阈值，
  不能固定在 0.35 上比。

> **阈值口径**：本文档所有「最佳」均取自八档扫描
> `{0.10,0.15,0.20,0.28,0.35,0.40,0.50,0.60}`，六个 run 的峰值均落在区间内部。
> 原始数据 `exp-2026-08-25-batch-sweep.json`。**每个 run 的最优阈值不同，
> 不要固定在 0.35 上做横向对比**——那会系统性惩罚置信度分布偏右的 run。
