## 预期对账

### 读数口径

预注册写的是「峰值」。前半程（iter < 13000）有检出几乎为零的退化评估（本臂 iter 1999 只出 211 个点、spike_recall 0.011），
所以峰值统一取**后半程（iter ≥ 13000）**，与 mini 系文档同口径。另报「后半程 `count_MAE_spike` 最低那次」同一 checkpoint 的全部指标（主读数，iter 17999）。

### 主判据的指标：计数这一条过线

| 预注册的线 | 实测（后半程峰值） | |
|:--|:--|:--:|
| `matched_F1@8` 峰值 ≥ 0.6627（p30 + 0.015） | 0.6493（iter 18999） | ❌ |
| 或 `count_MAE_spike` 峰值 ≤ 2.49（p30 ×0.9） | **2.4669**（iter 17999） | ✅（低 0.023） |
| 判否：F1@8 峰值 ≤ 0.6477 且 count 峰值 ≥ 2.77 | — | 未触发 |

### 机制读数（成立的必要条件）

| 预注册的门 | 实测 | |
|:--|:--|:--:|
| `point_nms/suppressed_frac` 在 5%~40% | 前 500 iter 均值 62%（初期 token 全挤在一起），之后各段 7.4%~9.5% | ✅ |
| `point_nms/starved_frac` ≤ 5% | 前 500 iter 62%，之后为 0 | ✅ |
| 推理-only 对照：本臂相对 p30 的增量要大于「p30 只开推理 NMS」的增量 | 见下表 | ✅ |

**推理-only 对照**（2026-10-22 补做，预注册写的是「训练完成后做一次」，当时没做）：

- 做法：`full/combo` 代码（开关全关时与 p30 代码等价），p30 自己的 `config.yaml` 与 `model_final.pth`，`--eval_only`，只改 `MODEL.MaskDINO.TEST.POINT_NMS_KAPPA`。qiuhao A100 GPU1，`MaskDINO-310`。
- 先用 κ = 0 复现：全部指标与 p30 训练日志末值逐项相同（count 2.7679、F1@8 0.6477、点数 13497、segm 81.97）。

### 判定

按预注册原文：计数这一条指标过线，机制读数三项都过，护栏全过，记 **成立**。

附注，判读时要一起看：

- **比较口径不对称**：这条线拿本臂的后半程峰值比 p30 的末值。p30 自己的后半程最低是 2.4645（iter 17999），和本臂的 2.4669 几乎一样。
- **同 iter 比，改善小**：后半程 13 次里 9 次低于 p30，平均 −0.17，末 4 次平均 −0.13。计数确实略好，但远不到「×0.9」那样的幅度。
- **定位与 p30 持平**：F1@8 同 iter 平均 −0.002。
- **架构差异**：本臂是 100 query，p30 是 300 query（预注册已声明）。

所以「成立」反映的主要是读数口径，不是计数上的实质改善。mini 上的同名臂判「歧义」，结论方向一致。
