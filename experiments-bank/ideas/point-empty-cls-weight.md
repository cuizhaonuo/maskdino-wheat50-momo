# 想法：给无小穗实例（Ni=0）的存在性损失降权

状态：**待验证** ｜ 提出 2026-08-26 ｜ 验证于
[exp-2026-08-26-point-empty-cls-weight](../experiments/exp-2026-08-26-point-empty-cls-weight.md)

前身是 [`memory-bank/idea.md`](../../memory-bank/idea.md) 的**第一条**
「Stage2 点存在性损失的正负样本失衡」，那里给的是更彻底的版本：
「(a) 只对 GT 类别为 wheat_2 的实例计算点损失」——等价于本文的 `weight = 0`。
该条自 2026-08-21 起被 `exp-2026-08-21-innercost` 标注为「优先级上升」，一直未跑。

## 现象

`criterion.py:406` 对每个外层匹配上的实例一视同仁地累加存在性 focal 损失：

```python
cls_loss = cls_loss + focal.sum()
```

`Ni == 0` 的 `wheat` 实例各贡献 P 个纯负样本。训练集里
`wheat : wheat_2 ≈ 11904 : 981`，无点实例占 92%。

## 假设与其修正

**提出时的直觉是「无点实例的负样本淹没了有点实例」，但这一条实测不成立。**

`vis_point_loss`（baseline，同一张图，39 个实例中 31 个是 wheat）：

```
本图合计=0.4818   坐标=0.0931(19.3%)   focal正=0.2520(52.3%)   focal负=0.1367(28.4%)
有点实例贡献 0.4353 / 无点实例 0.0465
```

**无点实例只占 9.7%。** focal 的调制因子 `(1-p_t)^γ` 已经把它们降权 25~100 倍
（这些槽的置信度只有 0.05~0.2）。换算到单个 slot：`wheat` 的 1550 个负样本槽贡献 0.0465，
而 `wheat_2` 内部 298 个负样本槽贡献 0.0902 ——
**单位代价上 `wheat_2` 自己的未匹配槽是 `wheat` 的约 10 倍**。
真正在压制正样本的是有点实例内部那些未匹配槽，不是那 31 个无点穗子。

### 【启动前补测，2026-08-26】上面那段只在收敛态成立，初期恰恰相反

冒烟跑到 iter 19（点头几乎未训练）时的 `loss_point_cls`：

| w | 1.0（baseline） | 0.3 | 0.1 | 0.0 |
|:--|--:|--:|--:|--:|
| `loss_point_cls` @iter19 | 7.8765 | 2.6472 | 1.1552 | 0.4807 |

**无点实例贡献 7.8765 − 0.4807 = 7.40，占 93.9%。**

原因是 focal 的抑制依赖于置信度已经压低：收敛态下负样本 `p≈0.05~0.2`，
`(1-p_t)²≈0.01~0.04`，降权 25~100 倍；而初始化时所有点都在 `p≈0.5`，
`(1-p_t)²=0.25`，**完全没有抑制**。

所以「无点实例淹没有点实例」**在训练初期成立（93.9%）、在收敛态不成立（9.7%）**。
上一节基于收敛态的 9.7% 不足以否定这个直觉——而初期恰恰是存在性头确定整体输出标度的阶段。
这条把本想法的预期收益调高了。

**另一个独立成立的理由：这部分监督几乎用不上。**
`maskdino.py:538` 推理时按 `pred_classes == spikelet_class_id` 门控，
`wheat` 实例**根本不输出任何小穗点**。这 50×31 个负样本监督只在
「某个 wheat 被误分类成 wheat_2」时才生效。花 9.7% 的损失预算买这个约束不划算。

## 修法

新增 `cfg.MODEL.MaskDINO.POINT_EMPTY_CLS_WEIGHT`（默认 1.0 = 现状）：

```python
w = 1.0 if Ni > 0 else self.point_empty_cls_weight
cls_loss = cls_loss + focal.sum() * w
```

只影响 `cls_loss`。`coord_loss` 不受影响（`Ni==0` 本就无匹配点、无坐标损失）；
`denom = max(num_pos, 1)` 只统计 Ni，也不受影响——权重纯粹作用在分子上。

扫 `w ∈ {0.3, 0.1, 0.0}`，`w = 1.0` 直接用已有的 `exp-0825-baseline`。
`w = 0` 时无点实例对点头完全无梯度，即 `memory-bank/idea.md` 的选项 (a)。

## 预期与判否线（跑之前写死）

- **`loss_point_cls` 必然下降，且这是纯算术，不是改善。** w=0 时约降 9.7%。
  **跨 run 比较绝不能引用 `loss_point_cls`**——三个 w 下它是不同的目标函数，
  只能比下游指标（mF1 / 计数 / AUC）。
- 匹配点置信度中位数应**略升**（共享头承受的负样本压力变小）。
- **风险指标：无点实例超阈值点数应上升**，这是降权的直接代价。
  参照值（同一张图）：baseline = 3，canonical = 18。
- 跨实例 AUC 预期**基本不动**——无点实例本就贡献极少梯度。

**判否线**：若三档的最佳 mF1 相对 baseline 变化均 **< 噪声地板 0.008**，
且跨实例 AUC 变化均 **< 0.03**，则该想法**在 overfit10 上被否决**。

若「无点实例超阈值点数」涨到 **3 倍以上**而 mF1 无增益，则判为**净有害**。

## 口径限制（先写下，避免事后找补）

这本质是**数据集构成**问题，而 overfit10 的构成不具代表性：

| | wheat_2 占比 | wheat 的损失份额 |
|:--|--:|--:|
| overfit10 | 8/39 = **20%** | 9.7%（实测） |
| 真实训练集 | 981/12885 = **7.6%** | ~25%（按每实例均值外推） |

**在 overfit10 上，即使 w=0 也只改变总损失约 9.7%，效应可能落在噪声里。**
本次为与已有六方对比表同口径而只跑 overfit10，
因此**否决结论仅限本配置**，不能外推到真实训练集——那里效应约大 2.5 倍。

另外 overfit10 是 train==test，端到端指标是拟合质量；
沿用 [exp-2026-08-26-val-generalization](../experiments/exp-2026-08-26-val-generalization.md)
的做法，对产出的 checkpoint 追加 val 检验。
