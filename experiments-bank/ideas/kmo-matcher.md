## 动机

内层匹配（每个配上的穗：P=25 个点槽 ↔ Ni 个 GT 小穗）是照 CLTR 的 matcher 移植的
（`小穗点回归方案.md`），但只移植了论文的 Eq.2：

    C = 5·‖p − p̂‖₁ + 2·focal(ĉ)

CLTR（Liang et al., *An End-to-End Transformer Model for Crowd Localization*, ECCV 2022, §3.3）
认为只用 L1 + 置信度的匈牙利缺少上下文，会给出不合理的配对，于是提出
KMO（K-nearest-neighbors Matching Objective），即 Eq.3：

    L_m^k(y_i, ŷ_j) = ‖y_i^p − ŷ_j^p‖₁ + ‖y_i^k − ŷ_j^k‖₁ − Ĉ_j,   y_i^k = (1/k)·Σ_k d_i^k

`y^k` 是 GT 点到其 k 个最近邻的平均距离；`ŷ^k` 由网络预测（"in our experiments, ŷ_j^k is
predicted by the network"），只在训练期的匹配里使用。论文自己的消融（UCF-QNRF）：

| | P | R | F1 | MAE |
|:--|--:|--:|--:|--:|
| Table 8：L1 + 置信度（Eq.2） | 80.89 | 79.17 | 80.02 | 91.3 |
| Table 8：+ KMO（Eq.3） | 82.22 | 79.75 | **80.97** | **85.8** |
| Table 9：k = 3 / 4 / 5 | | | 80.31 / **80.97** / 80.42 | 87.1 / **85.8** / 86.9 |

**效应量约 1 个 F1 点。** 这决定了下面判据的量级，也决定了单种子能不能分辨它。

L1 代价确实有歧义，这一点有本地证据：L1 可分离，两个预测点在 x、y 两个方向上都位于两个 GT
同一侧时，交换配对的代价**完全相同**，求解器只是在等价解里任取一个。单元测试中，随机点集上
77/300 个实例存在这种精确并列。这只说明 L1 几何本身有歧义；训练好的模型上它有多常见，由 M2 来测。

## 修法

新增 `cfg.MODEL.MaskDINO.POINT_KMO`（默认 False），以及 `POINT_KMO_K=3`、`COST_POINT_KNN_WEIGHT=5.0`、
`POINT_KNN_WEIGHT=5.0`。配置文件 `wheat_joint_single_stage_mini_kmo.yaml` 只打开这一个开关。

| 项 | 官方实现（本地 `/public/home/zncui/pycharm_project/CLTR`） | 本仓库 |
|:--|:--|:--|
| GT `y^k` | `dataset.py:173-204`：cKDTree 欧氏距离，查询 `k=num_knn=4` 后删掉第 0 列（点自身）再取均值，**实际是 3 个近邻**；N≤3 时对仅有的 N−1 个邻居取均值，N=1 时为 0 | `criterion.knn_mean_distance`，`k_eff=min(K, Ni−1)`，K=3。与官方逐值一致（测试误差 9e-8） |
| 坐标空间 | x、y、d 都除以同一个方形 crop 的宽度 | 在 `gt_rel`（框相对 [0,1]）上算，与 L1 坐标项同一空间、同一量纲 |
| `ŷ^k` | `channel_point=3`：`point_embed` 多出 1 维，过 sigmoid | 独立头 `point_knn_embed`（3 层 MLP），每槽 1 维，过 sigmoid |
| 匹配代价 | `cdist([x,y,d],[x̂,ŷ,d̂],p=1)×5`，与坐标同权 | `+ 5·|ŷ^k − y^k|` |
| 损失 | 3 通道共用一个 L1 ×5 | 独立的 `loss_point_knn`：只算匹配上的槽，L1 ÷ num_pos，×5 |

论文正文写 k=4，但它对应的是官方代码的 `num_knn=4`，这个数把点自身也算在内。K=3 复现的是官方代码的实际行为。
推理侧不动。`POINT_KMO=False` 时不建头、不加代价、不产生损失（回归验证见下文）。

## 离线统计（跑之前）

在 mini 集的全部小穗上计算，几何与训练一致：用掩码外接框（mapper 用的就是
`gt_masks.get_bounding_boxes()`）、框相对坐标、clamp，K=3。

| | mini train | val |
|:--|--:|--:|
| 有点实例 / 小穗 | 2754 / 43024 | 613 / 9747 |
| Ni mean / min / max | 15.6 / 7 / 31 | 15.9 / 9 / 24 |
| `y^k` 中位 / p10 / p90 / max | 0.154 / 0.124 / 0.198 / 0.393 | 0.158 / 0.125 / 0.205 / 0.433 |
| 全局常数预测的最优 MAE：`MAE_const` | 0.0230 | 0.0251 |
| **逐实例常数预测的最优 MAE：`MAE_inst`** | **0.0158** | 0.0179 |
| 方差中实例内部分的占比 | 59% | 59% |

三条推论：

1. **`y^k` 最大 0.43，sigmoid 输出足够覆盖；Ni ≥ 7，N ≤ K 的边界分支在本数据上不会触发。**
2. **KMO 只能通过 `ŷ^k` 在同一实例各槽之间的差异来改变配对。** 当 Ni ≤ P 时，`ŷ^k` 对所有槽取同一常数，
   只是给每一列加上一个常数，最优配对不变（单元测试已验证）。所以头若只学到每个穗的平均尺度，
   对匹配毫无作用。**M1 的参照线因此是 `MAE_inst`，不是 `MAE_const`。**
3. **量级偏小。** mini/baseline 末值 `loss_point_coord` 0.3877（×5），折合每个匹配点 |dx|+|dy| ≈ 0.078；
   而 `y^k` 在实例内部的离散只有 0.016。同权的 KMO 项只会在 L1 近乎打平的候选之间起作用，**预期是小效应**。

## 预期与判否线（跑之前写死）

对照 mini/baseline（`output_v2/exp-0922-single-stage-mini`）：同配置、同数据、同 schedule、同样从 ImageNet 起步，
唯一差别是 `POINT_KMO`。基线数值取自 `mini/baseline` 分支的
`experiments-bank/experiments/exp-2026-09-22-mini-baseline.md`（本分支没有这份文档，故直接写在这里）：

| 指标 | 峰值 | 末值 |
|:--|--:|--:|
| `spikelet/matched_F1@8` | 0.5783（iter 4499） | 0.5718 |
| `segm/AP` | 73.67（iter 5749） | 73.52 |
| `spikelet/count_MAE_spike` | 3.81 | 3.88 |
| `spikelet/spike_recall` | 0.9282 | 0.9103 |
| `spikelet/spike_precision` | 0.7090 | 0.6604 |

### 机制（先判，它决定主判据能不能读）

工具：`myscripts/backup/vis_process/kmo_match_diag.py`。它在 mini train 上以训练态做前向（不求梯度，100 个 batch），
只看最后一层 decoder 的内层匹配，并在**同一份预测**上分别求 KMO 配对和 L1-only（Eq.2）配对。
在 iter 2999 和最终 checkpoint 上各跑一次。

- **M1（头学会了实例内的上下文）**：在 L1-only 配对下（不让 KMO 自己挑对子）量 `ŷ^k` 的误差，
  要求 mean|ŷ^k − y^k| **< `MAE_inst` = 0.0158**。
  训练日志里的 `loss_point_knn` 是在 KMO 自己选的配对上算的，被选择效应压低，只作参考，**不作判据**。
- **M2（KMO 真的改变了配对）**：
  - 推翻率：KMO 配对的 Eq.2 代价比 Eq.2 最优高出 1e-5 以上的实例占比；
  - 换 tie 率：Eq.2 代价相同、但配对不同（只是在 L1 等价解之间换了一个）的实例占比。
- M1 不通过 → 判**「机制未启动」**：`ŷ^k` 在槽之间没有有效差异，本次结果不能用来评价 KMO。
- M1 通过，但最终 checkpoint 上推翻率与换 tie 率都 < 1% → 判**「KMO 在本设定下是空操作」**，端到端差异按噪声处理。

### 主判据：`matched_F1@8`（mini 配置已声明它对 recall 不敏感，可以直接跨 arm 比较）

| 条件 | 判定 |
|:--|:--|
| 峰值 ≥ **0.5883** 且末值 ≥ **0.5818**（都是基线 +0.01，与论文效应同量级），且护栏满足 | **成立** |
| 峰值 ≤ 0.5783 | **判否** |
| 峰值落在 (0.5783, 0.5883) | **歧义**：基线末三轮的平台波动约 ±0.001，但两次独立训练之间的种子方差从没测过。单种子分辨不了 0.01 以内的差异，需要两臂各补一个种子 |

### 护栏与观察量

- **护栏**：`segm/AP` 峰值 ≥ **73.17**（跌幅 ≤ 0.5）。KMO 只动内层点匹配，但 `ŷ^k` 的辅助损失会给共享的 decoder 加梯度。
- **护栏**：`count_MAE_spike` 峰值 ≤ **4.19**（3.81 × 1.1）。
- 观察：论文声称计数也改善（MAE −6%），这里只记录，不作判据。

## 实施前已完成的验证

**单元测试**（CPU，合成数据）：

| 项 | 结果 |
|:--|:--|
| `knn_mean_distance` vs CLTR `caculate_knn_distance`（K=3/4/5 × N∈{0,1,2,3,4,5,10,25,26,31} × 20，含重复点） | 最大误差 **9.2e-8** |
| `POINT_KMO=False` 时 `_inner_point_match` vs 改动前的函数体（300 例，Ni 0~31） | 配对**逐个相同** |
| `ŷ^k` 取常数时（300 例，Ni≤P） | Eq.2 最优代价不变；其中 77 例只是在精确并列的 L1 最优解之间换了一个 |
| `ŷ^k` 取随机值时 | 291/300 例偏离 L1 最优，说明 KMO 项确实在起作用 |
| 按论文 Fig.3 构造的玩具例（孤立 GT + 紧密三点簇） | L1-only 把两个槽配反（`{0:1, 1:0}`），KMO 按上下文配正（`{0:0, 1:1}`） |
| `loss_points` 端到端 | 只有开启时才多出 `loss_point_knn`；`COST_POINT_KNN_WEIGHT=0` 时坐标与存在性损失逐位不变；手算值一致；梯度能到达 `pred_point_knn` |

**回归验证**（xuyu GPU0，`SEED 42`，基线 mini 配置，每边 1 iter）：主仓库 `exp/single-stage-joint-mini`
与本分支 `POINT_KMO=False` 的 **128 项 loss 逐位相等**，参数表都是 732 个张量，没有 `point_knn_embed`。

**冒烟**（xuyu GPU0，与基线同 GPU 并发各跑 40 iter）：

- `loss_point_knn` 的 11 个 key（主输出、`_0`~`_8`、`_interm`）全部出现且有限；
- 训练 40 iter 墙钟 **3:28 vs 基线 3:31**，看不出额外开销；
- 训练结束后的 val 评估完整跑通（未训练模型各指标为 0，`count_MAE_img` 48.74，与基线 iter 249 的值相同）；
- 另跑一个 60 iter、warmup 5 的 run，确认头真的在学：`loss_point_knn` 从 1.60 降到 1.13 再到 0.81（原始值 0.32 → 0.16），
  aux 层和 interm 层同步下降。

## 已知风险

- **训练早期，KMO 项等于往内层代价里加噪声。** 在上面那个 60 iter 的 checkpoint 上，`ŷ^k` 的实例内标准差是 0.085（GT 只有 0.024），
  KMO 推翻了 **99%** 实例的 L1 配对。在头学会之前，内层配对有一部分实际上是随机的，这可能拖慢坐标头的早期学习。
  官方实现也一样（头同样从零开始），论文没有讨论这一点。M2 在 iter 2999 的读数会显示它是否已经稳定下来。
- **坐标空间各向异性。** `y^k` 在框相对空间里算，穗框纵横比中位数 2.3，沿短轴的距离被放大约 2.3 倍。
  选择这个空间，是为了让 KMO 项与 L1 坐标项在同一个量纲里比较（二者在 Eq.3 里直接相加）。

## 归因限制

KMO = 新的匹配代价 + `ŷ^k` 辅助回归损失，两者绑在一起。若结果成立，要把「配对改变」与「多任务正则」拆开，
需要再跑消融臂 `COST_POINT_KNN_WEIGHT=0`（只保留辅助损失）。本次不跑。

## 成本

6250 iter 约 7 h（mini/baseline 实测 7:05，与另一个 run 并发）+ M1/M2 诊断约 10 min。

## 结论（2026-09-23）

**预注册判定：「机制未启动」。** L1-only 配对下 `ŷ^k` 的误差为 0.0189，未过 < 0.0158 这条线。
按上文写死的规则，端到端结果**不能用来评价 KMO**。

但端到端数值远超主判据，且同向的信号不止一个：

| | KMO | 基线 | 线 |
|:--|--:|--:|--:|
| `matched_F1@8` 峰值 / 末值 | **0.5962 / 0.5954** | 0.5783 / 0.5718 | ≥ 0.5883 / ≥ 0.5818 |
| `segm/AP` 峰值 / 末值 | 74.21 / 73.87 | 73.67 / 73.52 | 护栏 ≥ 73.17 |
| `bbox/AP` 末值 | **71.23** | 69.26 | — |
| `count_MAE_spike` 峰值 / 末值 | 3.98 / **4.22** | 3.81 / 3.88 | 护栏 ≤ 4.19（峰值） |

- **M2：KMO 不是空操作。** 最终仍有 21.4% 的实例被它推翻 L1 配对，且推翻都发生在近乎打平的候选之间
  （代价差中位折合 L1 距离约 0.011）。
- **事后分解（非预注册）：M1 判据设计得过严。** M1 没过主要是因为逐穗水平偏差（0.012）；
  穗内信号其实存在，实例内相关系数 r = 0.47。它要求头赢过一个知道每个穗真实中位数的 oracle，
  把「组间水平」和「组内信号」混在一个 MAE 里同时考。**判定不改**，教训记入实验记录。
- **计数变差主要是标定偏移。** 两臂都有九成以上的穗被多数；KMO 多出的 0.34 MAE 几乎等于它多出的
  0.40 偏差。需要阈值扫描后比 best-vs-best。
- **不能归功于 KMO 的原因**：机制门未过；匹配代价与辅助损失绑在一起；两臂各只有一个种子。
  `bbox/AP` +1.97 是内层点匹配不会直接带来的，暗示辅助损失的多任务正则作用，或种子差异。

**下一步**（详见实验记录）：两臂各补一个种子 → 消融 `COST_POINT_KNN_WEIGHT=0` → 计数阈值扫描 →
效应仍在则上全集（`full/kmo-matcher`）。
