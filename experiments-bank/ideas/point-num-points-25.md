# 想法：NUM_POINTS 从 50 降到 25

状态：**部分成立** ｜ 提出 2026-08-21，2026-08-25 补充证据 ｜ 验证于
[exp-2026-08-25-point-num-points-25](../experiments/exp-2026-08-25-point-num-points-25.md)

原始论述见 [`memory-bank/idea.md`](../../memory-bank/idea.md) 的
「NUM_POINTS 从 50 降到 25」条目与
[exp-2026-08-21-innercost](../experiments/exp-2026-08-21-innercost.md) 的「新瓶颈 ②」。

## 现象

`exp-2026-08-21-innercost` 的模拟：把 P 个点在框内均匀铺开后与 GT 做同口径匈牙利匹配，

| 铺点数 | 平均 L1 | 等价 `loss_point_coord` | TP@8px |
|:--|--:|--:|--:|
| P=14 | .2728 | 1.364 | .142 |
| P=25 | .1658 | 0.829 | .231 |
| **P=50** | .0967 | **0.484** | .438 |
| 模型实测收敛值 | .0703 | **0.351** | — |

**纯随机铺 50 个点就能拿到 0.484，模型训到底才 0.351，仅比随机覆盖好 27%。**

## 假设

P=50 而每穗只有约 14 个 GT 小穗，匈牙利总能为每个 GT 找到碰巧靠近的 slot，
损失可以靠「把框铺满」压低，不必真的知道小穗在哪。P 降到 25 后随机基线抬到 0.829，
模型必须真的定位才能把损失压下去。

**2026-08-25 补充的第二条机制**（来自
[slot 分化诊断](../experiments/exp-2026-08-25-slot-specialization.md)）：
P=50 时 slot 的边际匹配频率被摊平到 `E[Ni]/P = 0.28`，而存在性头恰好停在这个频率
对应的 focal 平衡点上（相关系数 0.964）。P 降到 25 会把边际频率抬到 0.56，
**平衡点从 0.318 抬到约 0.46**，直接缓解「匹配点置信度峰值 0.30、卡在推理阈值 0.35
左边」这个计数漏检的根源。

## 修法

纯配置：`MODEL.MaskDINO.NUM_POINTS: 50 → 25`。运行期零代码改动
（该 key 只在 `maskdino.py:197` 和 `maskdino_decoder.py:180` 两处被读，改一处即全生效）。

全库实测 `Ni` 分布：train `min=1 / max=24 / mean=13.9 / p95=18`（981 个有点实例），
val `min=7 / max=22 / mean=14.0`。**P=25 刚好够覆盖 max=24，无需留余量。**
（`config.py:77` 原注释写「最多 23」，实测是 24，本分支顺手订正。）

副作用：`point_coord_embed` / `point_class_embed` 输出维度变化（50×2→25×2、50→25），
从 Stage1 热启动时这两层 shape mismatch、checkpointer 打 warning，属正常。

## 预期与判否线（跑之前写死）

- `loss_point_coord` 的收敛值应**显著高于** P=50 时的水平（不能再靠铺满取巧）。
  这是预期行为，**不得当作变差**。
- 匹配点置信度中位数应上升（平衡点 0.318 → ~0.46），超阈值点数上升。
- **判否线：`matched_F1@8` 到不了 0.45，则说明 P 不是主因**（沿用
  `memory-bank/idea.md` 里原本就写死的这条线）。
- 本条与 [point-focal-alpha](point-focal-alpha.md) **机制相同**（都是抬高 focal 平衡点），
  所以两者的置信度分布改善**不可叠加解读**；若两者提升幅度相近，
  应优先选代价更小的那个（α 是一行配置，P 会改变权重形状）。

## 结论（2026-08-25）

坐标损失升高（0.1016 → 0.1835）与置信度上升均**符合预期**；
最佳 mF1 +0.025（噪声地板的 3 倍），`count_MAE_spike` −24%。
但**判别力不升反降**：F2 跨实例 AUC 0.671 → **0.640**，这条本文没预测到。

原判否线（`matched_F1@8 < 0.45`）**在 overfit10 上没有分辨力**——
它是为 val 集标定的，而同期 baseline 自己就有 0.4935 也超过该线，故不能据此判成立。

P=25 与 [point-focal-alpha](point-focal-alpha.md) 同属**标定类改善**，不解决根因，
且需要改变权重形状、无法在已有 checkpoint 上热切换。若只为标定，α 或直接调阈值都更便宜。
